# 存档系统

## 玩家操作

- 标题主菜单顺序：开始新游戏、继续游戏、游戏进度、游戏设置、结束游戏。保持原来的左侧标题、右侧菜单、蓝色发光边框、字体和按钮风格。进度和关卡按钮只保留主名称，不添加小字说明或副标题。
- 开始新游戏：显示固定的三个进度栏。选择空栏创建进度，选择已有进度栏直接覆盖；统一进入教学关卡，不再选择起始关卡。
- 继续游戏：自动读取三个进度中保存时间最新的有效存档，包含自动、快速和手动存档；与当前选中栏和栏号无关。没有有效存档时禁用。
- 游戏进度：显示固定三个栏位，空栏不可载入。选择已有进度后提供「载入游戏」和「选择关卡」。每行右侧提供「删除」按钮，空栏禁用。
- 删除进度：点击该行右侧的「删除」，再点「确认删除」。取消或 Esc 返回进度列表。删除该栏的自动、快速、手动存档和关卡入口，栏位恢复为空；其他进度不受影响，「继续游戏」随剩余进度更新。不添加小字提示。
- 载入游戏：显示该进度的自动、快速和五个手动存档。
- 选择关卡：只显示该进度已有入口数据的关卡，不要求通关。载入该关最近一次正常进入时保存的状态，仍使用当前进度栏，不创建额外进度。
- 暂停／结算 → 重新开始本关：恢复本关当前有效的入口状态；暂停菜单需要再次点击确认。
- F1/F2：保存／读取当前进度的快速栏位。暂停 → 储存游戏：使用该进度的五个手动栏位。
- Esc／返回：返回上一层菜单。关卡较多时关卡列表可以翻页；进度栏固定三项，不翻页。

普通切场景完成、返回标题前以及成功恢复存档后，更新当前进度的自动存档。恢复失败后暂停写入，避免将部分恢复的状态覆盖到原存档。

## 数据组织

根目录：`Application.persistentDataPath/Saves`。

```text
profiles/slot-1/profile.json
profiles/slot-1/auto.json
profiles/slot-1/quick.json
profiles/slot-1/manual-1.json … manual-5.json
profiles/slot-2/…
profiles/slot-3/…
checkpoints/<checkpointId>.json
scene-templates/<contentHash>.gz
```

普通存档格式为 4，进度摘要格式为 2。只识别 `slot-1`、`slot-2`、`slot-3`。每次新游戏生成新的 `campaignId`；覆盖时先提交新自动存档和摘要，再删除同栏旧快速／手动存档。即使清理文件失败，身份不匹配的旧存档也无法载入。其他两栏不受影响。直接从编辑器运行游戏场景时只自动使用空栏，三个栏位都占用时拒绝自动创建额外进度或覆盖已有栏。

所有存档通过 SHA-256 校验，临时文件 flush 完成后原子替换。先写入口快照，再写普通存档，最后写摘要。摘要包含最新保存信息和各关最新入口引用；每份普通存档也持有入口目录，摘要丢失、损坏或落后时可以重建。继续游戏依据存档自身的 UTC 保存时间选择有效记录。

`GameSaveSystem.Profiles` 负责固定栏位、进度覆盖、入口目录、继续游戏与旧版清理；`GameSaveSystem` 负责捕获与恢复。GameSaveSystem 启用时，背包不再读写全局 PlayerPrefs，避免不同进度串用物品。

删除时先将整个进度目录移出固定栏位，再清理其存档与入口；清理中断时不会通过摘要重建重新出现。下次启动继续清理残留目录，仅处理原进度身份对应的入口，不影响同栏后来新建的进度。

## 入口数据与多场景关卡

入口记录在正常进入一个逻辑关卡、入场初始化和跨场景恢复完成后、玩家输入恢复前生成。它包含世界、角色、位置朝向、体力、背包容量及物品、成长技能、任务日志、地图兴趣点、发现记录、本关统计与此前结算结果。

再次正常进入同一逻辑关卡时，新入口数据替换该进度目录中的旧入口。同关楼层往返、普通保存／读档、选关载入和重新开始本关不会捕获新入口，防止把中途状态误当作入口。快照文件写入后不原地修改；「覆盖入口」通过将该关指向新快照实现。

入口目录属于整份进度：读取较早的普通存档、选择较早的关卡，都不会丢失已经记录的后续关卡，也不会把较新的入口引用还原为较旧的引用。恢复的是快照当时的游戏世界、访问历史与结算状态；目录按入口捕获时间合并。之后正常进入某关时重新生成入口，替换该关原有记录。无需增加通关标记、任务完成条件或额外解锁条件。

重新开始恢复完整世界缓存，清除入口后才访问的楼层缓存。入口未访问的场景按构建中的原始场景初始化。跨关沿用已有规则：清空携带物，保留规定的容量和成长，然后记录新关入口。关卡分组优先使用 LevelSceneGroup，Level1/Level2 前缀作为未注册场景的后备分组。实际入口场景和位置以快照为准。

SaveGameCatalogBuilder 在进入 Play 和构建前更新目录，也可以从 `Tools > Save System > Rebuild Catalog` 更新。新增状态需要接入 SceneTravelStateManager 的捕获与恢复接口；新增场景需要加入 Build Settings。场景结构、稳定路径和标识变更仍需相应的数据版本处理。

## 旧版清理

本版本不导入旧进度。启动时删除旧根目录下的七种存档文件及临时文件，并清理 `legacy-slot-*`、旧 GUID 进度目录中的已知存档和摘要。仅处理已知文件，不递归删除未知目录或遍历链接。固定三栏与共享场景模板缓存保留。旧格式 1、2、3 不再读取。
