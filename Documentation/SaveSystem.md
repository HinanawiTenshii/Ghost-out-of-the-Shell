# 存档系统

## 操作

- F1：覆盖快速存档；F2：读取快速存档，仅在关卡正常输入状态下响应。
- 暂停菜单 → 储存游戏：选择五个手动栏位之一；再次保存到同一栏位会覆盖。
- 暂停菜单或标题界面 → 读取／载入游戏：选择自动、快速或手动栏位。
- Esc／返回：退回上一层菜单。
- 正常切换到游戏场景后自动保存；返回标题界面前保存离开时的游戏状态。读取存档完成后也更新自动栏。

## 文件

目录为 `Application.persistentDataPath/Saves`。固定使用 `auto.json`、`quick.json` 与 `manual-1.json` 至 `manual-5.json`。

显示名称采用本地时间 `yyyy-MM-dd-HH-mm`，自动和快速分别加 A、Q 前缀。
外层保存 SHA-256 校验值；写入先完成临时文件，再原子替换正式文件。空栏位、校验失败、版本不匹配与不存在的目标场景不会直接进入场景恢复。

## 关卡与场景

优先读取 LevelSceneGroup 的关卡 ID、名称和成员。未配置分组时，Level1 前缀的场景归为一个关卡，其他场景作为单场景关卡。

每个首次进入的关卡记录进入时的收集物数量、入口快照以及构建中各成员场景的原始序列化定义。未访问场景从构建内原场景初始化；访问过的场景使用运行时对象快照。初始场景定义保留在文件中作为基线记录，不在运行时执行或解析 Unity YAML。

现有适配内容包括受控角色数据、位置、方向与体力，物品栏与物品身份／颜色／描述／魔力，成长及收集物数量，场景对象启用状态与变换、门锁／开关、拉杆、限时机关、提交工作台，任务及提前完成证据、兴趣点和物品发现历史，以及放置炸弹、魔像和纸箱状态。

运行时生成的任意新组件不会自动获得完整存档支持：添加新玩法时，应在 SceneTravelStateManager 的 ObjectState 中加入明确的状态和恢复接口。短暂视觉特效与寻路缓存不作为玩法状态恢复。

## 编辑器与构建

SaveGameCatalogBuilder 在进入 Play 模式前和构建前更新 `Assets/Resources/SaveGameCatalog.asset`。也可以执行 `Tools > Save System > Rebuild Catalog`。目录包含角色 prefab 引用及启用的构建场景定义，不会在构建过程中打开场景。新增场景仍需加入 Build Settings。

不要在发布后随意更改关卡 ID、场景名字或已存档对象的稳定路径。当前格式版本为 1；未来场景结构变动需要配套迁移，不保证旧存档兼容任意新版关卡。
