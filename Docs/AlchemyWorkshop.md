预制体目录：`Assets/Prefabs/Decorations/AlchemyWorkshop/`。

六件均为严格俯视的 XY 平面几何体，不显示桌腿、柜门、容器正面或透视侧壁。

| 预制体 | 内容 | 默认尺寸 | 碰撞 |
| --- | --- | --- | --- |
| Alchemy-Workbench | 木框绿面工作台，摊开的书、研钵与药瓶顶部 | 2.4 × 1.4 | 有 |
| Alchemy-ReagentRack | 木制分隔托架，六只彩色药剂瓶的顶盖 | 1.8 × 1.05 | 有 |
| Alchemy-Cauldron | 灰铁双耳坩埚、可变色药液与动态气泡；可提交材料、装瓶 | 1.6 × 1.4 | 有 |
| Alchemy-Distillery | 木底金属台、铜制锅盖、折返冷凝管与收集碗 | 2.2 × 1.4 | 有 |
| Alchemy-HerbTray | 衬布托盘、平放的草药与少量材料 | 1.4 × 0.9 | 无 |
| Alchemy-CrystalAltar | 灰石方台、铜色炼成环与晶石顶部切面 | 1.5 × 1.5 | 有 |

直接拖入地图使用，父对象中心为几何范围中心，可旋转 Z 轴和缩放。
根对象的 Geometric Alchemy Decoration 可编辑 Size、Solid（碰撞）、Wood、Stone、Accent 和 Sorting Order。
草药托盘适合放置在其他桌面上，叠放时将 Sorting Order 调整到桌面之上（例如 -2）。

使用现有家具的 Default 层、Sprites/Default 材质和 -3 渲染顺序，不额外发光；除下述炼药锅交互外均为装饰，不修改场景摆放。
每件通过一个顶点色 MeshRenderer 绘制；仅启用或编辑参数时重建网格。临时网格、材质及生成子对象会清理且不保存到场景。
木材保持褐色，石材/铁器保持灰色；高饱和绿紫色只用于药液、草药和晶石。

## 坩埚动态气泡

游戏运行时在药液中随机生成同色气泡，逐渐膨胀至最大，随后散成五颗小液滴并淡出。
移除了原来的两个固定气泡；编辑模式不播放动画。
气泡默认最大半径在 0.06875–0.10625 世界单位之间（原始尺寸增大 25%），与坩埚、父对象的缩放无关。颜色、轮廓和动画时间保持不变。
生成区域同时跟随 Size、Transform 及父对象的平移、旋转、非均匀缩放；已生成气泡也随药液移动，但保持世界大小。
完整气泡与破裂范围都限制在药液十二边形内，过小的坩埚会暂时停止生成，不会缩小气泡或溢出锅沿。
可在 Cauldron Bubbles 中调整半径、膨胀时间、生成间隔与破裂持续时间，或关闭 Animate Bubbles。
最多八个气泡共用一个额外动态网格，不逐泡创建对象；暂停时冻结，停用与销毁时清理。
`Tools/TestCauldronBubbles.ps1` 检查世界尺寸、旋转/非均匀/镜像/剪切变换、边界、生命周期及暂停。

## 可挂载的临时效果区域

脚本：`Assets/Scripts/Interaction/TemporaryCharacterEffectArea.cs`。通过 Add Component → Interaction → Temporary Character Effect Area（临时效果区域），或把脚本拖到对象上即可添加，不需要特定预制体。

- `Area Collider` 指向本对象或子对象的 **Collider2D**，需启用 **Is Trigger**。留空会自动寻找；在没有任何碰撞体的对象上通过编辑器添加脚本时，会创建默认 3×3 的 BoxCollider2D Trigger。已有实体碰撞体不会被自动转为 Trigger，已有形状、大小和位置不会被改写。支持 Box/Circle/Polygon 等 2D 形状，不要求区域自身添加 Rigidbody2D。
- 默认进入后每 **0.3 秒恢复 1 点生命**，第一次恢复需在区域内停留 0.3 秒；最多恢复到角色生命上限。玩家与 NPC 使用相同规则，不治疗幽灵、不复活死者，不产生攻击/敌意/受伤声音或角色受击抖动。角色有多个实体碰撞体时，每个区域只计时一次。
- 生命增加时，现有 HUD 爱心使用与受伤相同的闪烁高亮，但不新增抖动；满血时不反复触发闪烁。切换控制角色时仍沿用原本 UI 初始化，不把切换看作治疗。
- 离开范围、传送离开、角色停用、区域或 Collider 停用后移除该区域效果，重新进入重新计时。暂停/读档时不推进治疗。当前生命值继续使用既有角色存档数据，不保存或跨场景携带区域计时器。多个独立区域各自生效，同一区域不按碰撞体数量叠加。
- 与现有加速区域一样自动添加 `CameraVisionStreamingExempt`，防止区域自身因摄像机距离被卸载，导致仍在活动的远处 NPC 漏掉治疗；不会唤醒或治疗被距离加载暂停的角色。手动停用区域仍立即停止效果并清理气泡。
- 可调整 `Health Per Tick`、`Tick Interval`，或关闭 `Restore Health` 只使用扩展事件。`On Character Entered`、`On Effect Tick`、`On Character Exited` 均传入对应的 `ZeldaCharacterData`，供以后接入其他区域效果；满血时周期事件仍会正常触发，但不会继续回血。

运行时自动生成与炼药锅一致的绿色气泡：随机浮现、逐渐长大、破裂为五颗液滴后消失。颜色、半径、生长时间、生成间隔、破裂时间和渲染顺序均可配置。气泡与破裂范围按选定 Trigger 的实际形状采样，生成区域跟随位移/旋转/缩放，气泡半径保持世界单位，过小的区域不强行缩小气泡。矩形与多边形使用实际边界净距检查，圆形等使用物理形状周界采样；不是在旋转碰撞体的矩形包围盒外侧生成。

默认排序为 Default / -2（与炼药锅气泡一致），如果挂载到排序更高的表面，可提高 `Bubble Sorting Order`。最多八个气泡共用一个动态网格，不给每个气泡创建对象、碰撞体或灯光，不修改对象原有材质/视觉；区域停用/销毁时释放临时网格和材质。暂停冻结气泡，关闭 `Animate Bubbles` 或禁用 Trigger 清空气泡。

验证：`Tools/TemporaryEffectArea.Validation.targets` 用于完整项目编译；`Tools/TemporaryEffectAreaSmoke.cs` 在隔离 Unity Play Mode 使用真实物理查询、角色、数据源和 HUD，验证治疗周期、上限、重复碰撞体、退出/停用/重入、圆形与子对象 Trigger、幽灵/死亡/跨场景过滤、爱心闪烁、扩展事件安全和气泡生长破裂/世界尺寸/释放。气泡预览为 `Docs/TemporaryEffectArea-preview.png` / `.gif`。已有炼药锅代码和关卡摆放不变。

`Tools/TestAlchemyWorkshop.ps1` 验证几何边界、三角形方向、顶点预算、预制体与 meta 引用，并从实际生成几何绘制 `Docs/AlchemyWorkshop-preview.png`（非 Unity 实机截图）。
`Tools/AlchemyWorkshop.Validation.targets` 用于尚未被 Unity 重新生成的工程文件的编译检查。

## 可拾取炼金材料与玻璃瓶

另新增四个可直接拖入地图的预制体，统一放在 `Assets/Resources/PickupItems/`，沿用现有物品图标、呼吸、E 拾取、物品说明、背包、Q 放下及存档机制：

| 预制体 | 名称 / ID | 行为 |
| --- | --- | --- |
| RedHerbPowderPickupItem | 红色草药粉 / red_herb_powder | 仅拾取与放下，R 无效果且不消耗 |
| GreenHerbPowderPickupItem | 绿色草药粉 / green_herb_powder | 同上 |
| BlueHerbPowderPickupItem | 蓝色草药粉 / blue_herb_powder | 同上 |
| GlassBottlePickupItem | 玻璃瓶 / glass_bottle | R 向前投掷并消耗一个；Q 完整放下，可再次拾取 |

草药粉以 Minecraft 火药图标的不规则粉末簇和零散颗粒为造型参考，使用自行绘制的三色像素图案，没有导入原游戏贴图；粉末本身不可直接服用，可用于下述炼药系统。玻璃瓶使用半透明青色玻璃、左右对称的瓶颈/肩部/亮面反光、镀金瓶口/瓶底和居中紫色宝石装饰，表现为空的精致药水瓶。地面、背包和飞行外观共用同一套对称图案。三色草药粉和玻璃瓶每格最多 3 个；只有物品种类和实例配置一致时才合并，独立修改过的投掷参数等不会丢失。

三色草药粉在场景中持续产生与 `Powder Color` 同色的魔力微粒：从粉末堆内部浮现，向画面上方飘升并向左右随机散开，逐渐缩小、淡出后消失。旋转物品不会改变向上的漂浮方向，已经飘出的微粒也不会随物品移动而被拖拽。背包与说明窗口保留静态图标，不生成粒子。

`HerbPowderPickupItemVisual` 的 `Rising Magic Particles` 可调整开关、每秒数量、寿命、上升速度、扩散速度与大小。默认每秒 8 颗、平均寿命 1.6 秒，每堆最多 32 颗，共用一个 ParticleSystem/Renderer；没有逐颗 GameObject、碰撞或额外灯光。粒子使用正常场景渲染层级，继承物品的遮罩设置，不穿透视野遮罩；暂停时冻结，拾取/隐藏/距离卸载时停止并清空，重新启用恢复，销毁时释放临时材质。不会改变草药粉的任何使用功能。

`Tools/HerbPowderParticlesSmoke.cs` 在隔离 Unity 工程验证三色、上升/扩散/渐隐、旋转、暂停、隐藏与卸载、资源释放及实际 GPU 动画。预览为 `Docs/HerbPowderParticles-preview.png` 和 `.gif`。

玻璃瓶组件可配置 `Throw Speed`（默认 6 世界单位/秒）及 `Investigation Radius`（默认 5，0 禁用吸引）。配置随物品实例写入 InventoryState，因此经背包、丢下、跨场景携带或背包存档恢复后保留。R 不走附近纸箱的存入快捷路径，且沿用通用伸手动画。

投出后沿当前面向飞行并旋转，首次接触实际碰撞体或满 6 秒即碎裂，播放少量淡青玻璃/金色碎片及已有玻璃音效。普通交互、权限区域触发器不是物理障碍；实体碰撞体、可受伤对象和 Blocks/Hidden Blocks 层触发式墙体会使瓶子碎裂。使用扫掠检测与初始重叠检测，忽略投掷者及临时使用物品，不能越过紧贴身前的薄墙。

命中角色或可受伤物品时只对该目标结算一次 AttackPower = 1 的普通攻击，不随玩家攻击力增长、不产生炸弹式范围爆炸；仅超时碎裂时不额外造成范围伤害。直接击中角色仍使用现有正常受击/敌意规则。碎裂处半径内的同场景 AI 收到现有调查指令，前往落点；不对投掷者或玩家当前控制角色发出调查命令。先唤醒附近被距离加载暂停的对象，调查状态随后沿用 AI 自带的防卸载机制。飞行体也有短距离预加载区域，不会因离开摄像机而冻结或漏撞。

碎裂声音复用 `Audio/GlassBreak`，来源仍为音效登记表 S7（没有新增下载或更改音源文件）。本次不修改关卡摆放与其他物品行为。飞行中的瞬态投掷物随所属场景卸载而清理，与现有子弹一致，不加入飞行状态存档。

## 炼药与独立临时效果

`Alchemy-Cauldron.prefab` 已挂载 `AlchemyCauldron`，已有该预制体的实例会继承功能；也可给现有炼药锅手动添加此脚本并指定 `Cauldron Visual`。不会自动向关卡额外放置材料或药水。

靠近锅后，在物品栏选中草药，按 **E** 每次提交一份。凑齐三份即完成炼制，顺序不影响配方；提示显示已提交的数量或成品名称。选中玻璃瓶后按 **E** 装瓶，消耗一个空瓶并获得一个药水。装瓶时若无法容纳成品，锅液和空瓶均保留；满背包中最后一个空瓶可直接换成药水。空锅为深暖灰，和所有成品区分；炼制完成及装瓶后均以约一秒渐变改变药液和气泡颜色。颜色按三色草药比例混合，不逐帧重建锅体网格。

药水分别位于 `Assets/Resources/PickupItems/Potion-{Kind}.prefab`，每种独立预制体和物品 ID。沿用 E 拾取、Q 放下、R 饮用、说明与背包保存；每格一个，无法存入纸箱。成功饮用任何一种药水（包括剧毒）后，返还一个默认配置的玻璃瓶；优先合并配置相同、未满三只的瓶堆，否则直接放入刚消费药水的格子，满背包也能饮用。不同投掷参数/颜色的瓶子不会被合并或改写。失败饮用不消耗药水、不凭空返瓶，背包回调再次使用/丢弃会被拦截。原玻璃瓶的 R 投掷功能保留，装药必须使用锅旁的 E。

回响成功保护当前受控角色时，同场景内正在对该角色警告/敌对的 NPC 会清除目标、报复/追击/警告记忆和待处理调查，立即进入原有返回状态。包括骷髅与已激活的自动人偶，但不关闭人偶、不改变其敌我规则；距离加载暂时隐藏的合格 NPC 通过加载系统恢复，不启用作者主动停用的对象。其他 NPC 间的战斗、其他场景以及非警告/敌对状态不受影响。失败回溯、非致命伤害、非玩家身体触发回响、剧毒和附身切换死亡均不会触发此清理。

回溯角色与被重置 NPC 的旧近战/角色攻击会被中断，已独立生成的炸弹爆炸等效果保持不变；致命攻击本次接触也不会在回溯之后继续击退角色。仅防止同一帧的残留攻击回调/AI 感知覆盖返回状态，不额外添加停战或隐身时长。下一帧起如重新发现玩家或发生新攻击，仍按原规则响应；未发现新目标则正常返回初始位置。未改变回响 120 秒、1 秒免伤、恢复生命或安全回溯位置的规则。专项验证入口为 `Tools/EchoRecoverySmoke.cs`。

## 注液器（药水注入与可配置条件接口）

预制体：`Assets/Prefabs/Decorations/LiquidInjector.prefab`。俯视铁制储液罐、红色束箍和手动 T 形压杆，中心液体窗口当前为深灰色；由一个顶点色网格组成，使用正常场景排序（Default / 5），不增加灯光、不穿透视野遮罩。根节点带实体碰撞体。可直接拖入场景，不自动摆放或改动任何现有区域。

配置方式：

1. 在 `LiquidInjector` 的 `Linked Areas` 数组中拖入多个带 `TemporaryCharacterEffectArea` 的场景对象。
2. 在物品栏选中任意炼制药水，由存活的受控角色靠近设备按 E，消耗一瓶药水并返还一个玻璃瓶（与饮用规则一致），不对操作角色直接施加饮用效果。选中药水本身满足新注液流程的条件，不需要预先勾选旧的 `Condition Satisfied`；无有效绑定区域或交换失败时保留药水。
3. 成功时播放通用伸手动作，一次应用到所有有效绑定区域。重复引用只处理一次；忽略空引用和其他场景对象；停用区域更新配置但不会被强制启用。幽灵不能操作，暂停/阅读/人偶控制期间不可使用，并有 0.5 秒交互冷却。
4. 注液器中心窗口、区域气泡改为对应药水颜色。新注液覆盖旧区域配置，并关闭原有持续回血，避免药水效果与默认回血意外叠加；区域内已有角色在下一次物理更新同步切换效果。
5. 旧的无药水配置接口仍保留：`Condition Satisfied` 默认未勾选，调用 `SetConditionSatisfied(true)` 或在编辑器勾选后，可应用 `Injection` 预设；其包含原有回血配置和新的药水模式。旧流程 `Recolor Bubbles` 默认关闭，保持原区域气泡颜色，开启时使用 `Injection / Bubble Color`。解锁和配置本身不会自动注液。

药水区域规则：

- 进入时施加同款药水的效果；持续型效果为原药水时长的两倍（例如巨力 60 秒、幻隐 30 秒、回响 240 秒）。在区域内计时冻结，离开后开始扣减；HUD 计时环以本次实际总时长计算。
- 再次进入同类区域重置时长。多个同类区域重叠时，离开其中一个不会开始倒计时，需离开所有仍生效的同类区域。
- 不同药水区域使用独立的单一「区域 Buff」位置，后来进入的类型覆盖此前的区域效果；离开新区域不会自动恢复较早重叠的异类效果。主动饮用的其他药水和技能效果不被区域替换清除。
- 活力仍按原药水规则恢复 6 生命或满生命时增加 3 临时上限；灵能仍恢复 4 能量或满能量时增加 2 临时上限；剧毒仍立即死亡。即时恢复/死亡只在进入时执行，不每帧重复。灵能不让 NPC 修改玩家的全局附身能量。
- 幻隐主动破除、回响死亡回溯消耗后，站在区域内不会立即重新获得；需要离开后重新进入。原本的回响跨场景失效规则不变。
- 暂停、读档、同类/异类重叠和距离卸载均使用原有 Buff/存档系统，区域来源单独保存；读档重建重叠关系，不把读档视为再次饮药。

扩展接口：

- `ConfigureInjection(EffectSettings, Color, bool changeBubbleColor = false)` 设置下一次注液的配置和指示色，不立即应用。
- `TryInject()` 返回成功/失败，`Inject()` 是可连接 UnityEvent 的交互入口；二者仍检查当前角色、距离和冷却。选中药水时走药水交换流程，否则沿用旧的解锁条件和预设流程，并非绕过交互限制的远程指令。
- `On Injected` 事件仅在注入成功后调用一次，参数为操作角色，供以后连接任务、场景机关或物品逻辑；回调再次注液会被拦截。
- `TemporaryCharacterEffectArea.CaptureEffectSettings()` / `ApplyEffectSettings(...)` 允许其他效果逻辑直接读取/更新区域配置；`EffectSettings.ForPotion(kind)` 创建标准药水区域配置。改变效果不伪造进入/退出事件，区域内原有角色直接改用新设置，并重新开始计时。现有 `On Character Entered` / `On Effect Tick` / `On Character Exited` 扩展接口保留。

跨场景快照及磁盘存档分别记录注液器条件、待注入配置、当前指示色，以及每个区域最终生效的设置。恢复时不重新注液、不触发 `On Injected`，因此不会覆盖另一台注液器后来写入的区域效果。旧存档缺少这些状态时保留场景默认配置。

### 狂战与幻隐的角色视觉

狂战生效时，角色的普通近战攻击使用原有武器图形，在前方约 110° 的弧内挥动并伴随短距离横向移动；石块、书本等居中图形也具有可见的横扫位移。仅动画表现变化，原有狂战攻击判定区域、伤害、单次命中去重和攻击时长保持不变，爆炸与冲击波不参与横扫。旋转使用独立视觉节点，避免不等宽高缩放使剑、锤等在挥动时变形；眩晕或回响打断会同时隐藏武器视觉。

幻隐生效时，本体使用 45% 不透明度，保持原来的颜色和受击/恢复闪烁。不修改身体颜色缓存，而在原渲染材质上增加独立的透明度乘数，避免反复刷新导致越来越透明；不影响头顶图标、视野、碰撞、排序或遮罩。到期、主动破隐、死亡或脚本停用时撤销透明度；幽灵形态仍使用自己的视觉规则。
