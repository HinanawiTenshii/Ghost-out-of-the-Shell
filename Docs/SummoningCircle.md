# 召唤法阵

预制体：`Assets/Prefabs/Decorations/SummoningCircle.prefab`。

## 配置

1. 将预制体拖入场景，在 `Summoning Circle` 中设置 `Area Size`（默认 12 × 10）和 `Area Offset`；选中后可在 Scene 视图拖动紫色矩形边缘。范围随对象的旋转、缩放变化，不产生碰撞。
2. 在 Project 窗口使用 **Create → Cogitans & Extensa → Character Persistent Identity**，为六名指定角色分别创建独立的身份资产。
3. 将身份资产放入对应角色数据脚本的 **Persistent Identity**，再将同一资产放入法阵的“绑定角色 1～6”。角色可以来自其他场景，身份不依赖名称、Hierarchy 路径或直接场景引用。不同角色不要共用同一身份。
4. 在“召唤角色预制体”中指定需要生成的角色预制体（不能使用场景实例）。默认未绑定，不擅自决定召唤哪一种角色。
5. `Summoning Circle Visual` 可调整法阵半径、紫色色调、渲染顺序、每名角色的碎片数量。默认每名 72 片，吸收时间 1.8 秒。
6. `Summoning Ritual`：默认汇聚 3 秒、喷发 3 秒、爆散尾声 1.4 秒；可分别编辑时长。`Eruption Shake` 控制喷发期间的屏幕抖动，`Ritual Volume` 控制三段音效音量。

## 行为与保存

- 仅接收**当前法阵所在场景、矩形范围内**死亡的绑定角色。范围外死亡不计入，幽灵不是献祭对象。
- 普通伤害、药水致死、切换附身导致的肉身死亡、技能自毁等均通过统一死亡入口处理；正常死亡通知和玩家回到幽灵的逻辑仍保留。
- 有效献祭替换原有死亡碎裂/复活表现，角色立即移除，碎裂成紫色粒子，先散开再加速飞向随机空闲水晶。粒子到达后水晶才点亮，已占用的水晶不被重复选取。被吸收的骷髅也不会再次复原。
- 每个身份只贡献一次；需要六名不同角色。六颗全亮后先从六个水晶向中心汇聚紫色像素粒子，随后向上喷发，最后向四周爆散；爆散开始时在法阵中心生成指定角色，沿用该预制体的属性和 AI，不自动夺取玩家控制。
- 只有喷发期间、法阵本体进入游戏摄像机画面时产生轻微震动；移出画面、暂停、加载或结束喷发后停止。新增声音仅作表现，不施加伤害、不吸引 AI。
- 默认为一次性召唤。保存已用身份、亮灯状态、飞行中的粒子进度、仪式阶段和阶段已用时间；中途读档/返回场景会续接对应视觉与音频。角色仅在爆散开始时生成一次，读档不重复生成；生成的角色也进入现有场景/存档恢复流程，角色死亡后不再次补生。旧存档中已召唤的法阵不会重播仪式。
- 角色身份随玩家跨场景、角色重建及读档保留。法阵使用距离加载豁免，避免视野外献祭漏记；死亡时才查找法阵，不逐帧扫描场景角色。粒子使用复用的批量网格，没有逐粒子 GameObject 或物理碰撞。
- 多个法阵范围重合且绑定同一角色时，该次死亡只由最近的可接收法阵吸收，不重复献祭。

没有改动任何已制作关卡或已有角色的默认绑定。
