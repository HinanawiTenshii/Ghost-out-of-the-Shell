# 技能跨场景目标修复

## 原因与范围

场景切换会通过 `DontDestroyOnLoad` 保留当前受控角色，角色的 Unity 存储场景因此不同于当前关卡。原先恐惧咆哮把范围对象放到施法者的存储场景，再据此筛选 NPC；跨场景后会排除当前关卡全部 NPC。发号施令、骨牌选取/预览和附身转移粒子也存在直接比较存储场景的问题。

`ZeldaRuntimeRegistry.GetGameplayScene` 将常驻对象解析为当前活动关卡，普通对象仍保留其自身场景，避免误选另一个已加载关卡的角色。技能场对象、骨牌运行对象和标记运行对象归属实际关卡，不改变角色的跨场景持久化设计。

运行时新增的 `CameraVisionStreamingExempt` 现在始终生效，而非仅在遥控傀儡期间生效，防止标记/骨牌成员被视野流式管理暂停。未改变技能费用、半径、持续时间和敌我规则：恐惧咆哮仍仅影响非玩家控制角色，不重复刷新已有眩晕。

## 验证

运行 `Tools/TestSkillEffects.ps1`：提取生产代码中的场景解析、咆哮扫描及参数初始化、AI 眩晕/命令接收、命令施放、骨牌目标排序、战斗专精施放和计时方法，使用轻量 Unity 数据替身执行 67 项断言。覆盖普通/跨场景常驻施法者、半径边缘、延迟进入范围、已眩晕/死亡/玩家/非激活排除、三级眩晕、命令人数与扣费、骨牌升级和二级战斗专精恢复。另检查技能预览、附身粒子、流式豁免、力量加倍进入攻击判定及幽灵形态关键接线。

完整 C# 项目编译通过。上述测试不等于 Unity Play Mode 实测；最终还需验证 Unity 生命周期、输入与场景流式加载的联合行为。

## 游戏内验收

1. 附身巨兽后先在当前场景释放，再跨场景释放；半径内 NPC 都应眩晕。释放后的一秒内进入范围者也生效，玩家与已有眩晕者不重新眩晕。
2. 二级半径 3.5、三级眩晕 5 秒；每次消耗 3 点 E.G.O。
3. 跨场景后对警告/敌对 NPC 使用发号施令，最近 3/5 名进入返回状态并无视玩家 5 秒。
4. 跨场景后骨牌预览与实际施放目标一致；绑定成员远离视野后伤害/死亡关联仍有效。
5. 标记目标离开视野后再次发动仍能转移；普通附身过程能持续显示转移粒子。
6. 战斗专精二级三秒内每秒恢复一点生命；幽灵形态时长、消耗与结束恢复正常。
