# 机关人偶：绑定的魔力遥控器

适用于原有噬菌体造型的 `ClockworkPuppet`，不改变武装魔像的 `PuppetRemotePickupItem` 群体开关道具。

- 背包中的机关人偶按 **R** 部署并接管后，其原槽位替换为 **魔力遥控器**；放入纸箱驱动的分支也支持。
- 控制时按 **R** 退出，随后选中对应遥控器再按 **R** 可重新接管。同一次按键不会导致刚进入就立即退出。
- 遥控器按 **Q** 直接消散，不产生地面物品、不存入纸箱；如果正在控制该人偶，则同时退出控制。人偶本体仍留在原处。
- 按 **E** 回收对应人偶时，在遥控器所在格替换为人偶；满背包也可完成，保留剩余能量、名称及颜色。如果遥控器已经丢弃，则回收需要一个空格，下一次 R 部署时会重新生成遥控器。
- 人偶能量耗尽（包括纸箱内耗尽）时移除对应遥控器；装载它的纸箱被打坏也会移除。多个遥控器通过人偶唯一身份分别绑定，拖动槽位不影响关系。

## 跨场景与存档

- 人偶留在部署场景，遥控器随物品栏跨场景携带。离开时先退出遥控，再保存场景快照；返回时不会自动抢占镜头和输入。
- 返回原场景后可再次按 R 接管。其他场景（即使原场景同时加载）无法连接，给出提示且保留遥控器；不会自动传送玩家或把人偶带过来。
- 绑定复用 `ItemInstanceId`，普通人偶保存 `itemInstanceId`，纸箱保存 `storedItemInstanceId`，不使用 Unity 运行时实例编号。已有场景／磁盘存档路径保存这些身份与剩余能量，无需改变存档格式。
- 场景卸载、回收、出箱转移不等同于能量耗尽，`OnDestroy` 不删除遥控器。只在明确的耗尽／破坏路径移除，避免在过场或读档时误删。
- 读档／过场恢复尚未完成时不允许重新接管；恢复闲置的纸箱人偶不会打断另一个已恢复的人偶控制。

## 验证

`Tools/TestClockworkPuppetRemote.ps1` 执行生产代码中的物品栏替换、回收、唯一身份、重新连接与状态序列化逻辑，并检查 R/Q、纸箱、跨场景集成。引擎服务在此脚本中为测试替身。

`Tools/ClockworkRemoteSmoke.cs` 用于隔离的 Unity 测试项目，加载实际生产脚本与预制体，验证物品栏操作、真实场景卸载／快照重建、Unity JSON 序列化和纸箱分支。不应作为游戏组件装载。

本次验证结果：54 项逻辑／视觉断言、JSON 往返与集成检查通过；Unity 2021.3.16f1c1 隔离运行 30 项断言通过；完整 C# 与编辑器项目编译为 0 警告、0 错误。原有机关人偶行走、像素视觉、纸箱炸弹模式、互动伸手和武装魔像遥控器回归测试通过。
